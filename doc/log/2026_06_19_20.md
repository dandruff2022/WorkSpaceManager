## Issue Log & Resolutions (Platform by Platform)

### 1. ChatGPT
*   **Issue A: React Clipboard Binding Constraints & Firefox Sandbox Restrictions**
    *   *Type*: Execution Context / Framework event-binding.
    *   *Details*: ChatGPT's React app binds event listeners directly to a local, lexical reference of `navigator.clipboard.writeText` when the page initializes. Overriding the global API later in the devtools console has no effect on React's bound handler. Additionally, Firefox restricts non-trusted click actions from writing to the OS clipboard, triggering standard React error handlers.
    *   *Resolution*: Implemented a clean DOM-text scraper fallback. When the console wrapper misses the copy event within the 1-second timeout, the script scrapes the text directly from the turn container.
*   **Issue B: Premature Generation Completion (Hidden Stop Buttons)**
    *   *Type*: State Observer False Positive.
    *   *Details*: During response generation, the observer timed out because ChatGPT keeps the "Stop generating" button in React's virtual DOM element pool (simply hiding it via CSS or properties) rather than destroying it. Querying for the selector returned a hidden element, keeping `isDone` false.
    *   *Resolution*: Modified `stepWaitForGeneration` to query all matching stop elements and filter them by visibility (`offsetWidth > 0 || offsetHeight > 0`).

### 2. Claude.ai
*   **Issue: Subelement Turn Resolution in Chained Sequential Copying**
    *   *Type*: Sibling / Parent Traversal collision.
    *   *Details*: Claude's `messageTurnSelector` matches the inner message body element (`div.font-claude-message`). Because Claude places copy/thumbs-up action buttons outside this text container in a sibling block, querying `turn.querySelectorAll(copyButtonSelector)` returned 0 elements, causing Step 9 (sequential history verification) to fail with 0 matched turns.
    *   *Resolution*: Restructured Step 9 to locate all valid copy buttons on the page first, and then dynamically resolve their unique parent turns by walking up the DOM using our shadow-aware `findParentTurn` method.

### 3. Gemini
*   **Issue: Account Profile Click Collision**
    *   *Type*: Selector Collision.
    *   *Details*: The old `newChatButtonSelector` queried `a[href*="/app" i]`. Since both the main brand logo and the Google user account profile switcher link to `/app` (often followed by query strings), the script clicked the profile icon and opened the user profile dropdown instead of starting a new chat.
    *   *Resolution*: Hardened the selector to use `a[href*="/app" i][aria-label*="new" i], [aria-label*="new chat" i], [data-testid*="new-chat" i]`, target-matching the actual action button.

### 4. Microsoft Copilot
*   **Issue A: Text Input State Hydration Failure**
    *   *Type*: React State Sync / Controlled Components.
    *   *Details*: Injecting text using `input.value = text` directly bypassed React's value tracking hook. Copilot still perceived the input as empty, displaying only the Voice (microphone) button and hiding the Send button.
    *   *Resolution*: Accessed and called the prototype descriptor setter (`Object.getOwnPropertyDescriptor(HTMLTextAreaElement.prototype, 'value').set`) to update React's state wrapper, dispatching bubbling `input` and `change` events.
*   **Issue B: Copy Button Detachment**
    *   *Type*: DOM Lifecycle.
    *   *Details*: Triggering `targetBtn.click()` caused Copilot's React framework to immediately re-render or replace the action buttons block. Attempting to traverse parent elements *after* the click returned `null` because the copy button had already been detached from the active document tree.
    *   *Resolution*: Pre-resolved the `targetTurn` container reference *prior* to triggering the button click.
*   **Issue C: Reactions Bar Target Collision**
    *   *Type*: Selector Walk-up Collision.
    *   *Details*: Walking up the parent tree of the copy button matched the toolbar container `message-item-reactions` (since it contains the substring `"message"`). The fallback text scraper ended up copying button labels like `"Copied"` rather than actual response text.
    *   *Resolution*: Hardened the parent resolution helper to explicitly skip elements whose class names or data-testids contain `"reactions"`, `"actions"`, or `"controls"`.

## Code Restructure & Refactoring

In `test/sandbox_tester.js`, we successfully modularized code blocks to resolve redundancies:
1.  **`getValidCopyButtons(container)`**: Centralized the copy button filtering query, excluding copy elements inside `pre`, `.code-block`, and `code` tags.
2.  **`findParentTurn(element)`**: Consolidated shadow-root-aware parent walks and reactions-skipping loops into a unified, reusable helper.
3.  **`hydrateInputValue(input, value)`**: Standardized input injection using the native descriptor setters for React inputs.
4.  **Sequential Chain Copy (Step 9)**: Refactored to map turns directly from the valid copy buttons on the screen, improving platform independence.
