## 1. Scope and Goals of Phase 1.4

We established the execution plan for Phase 1.4 (`doc/plan/phase_1.4_plan.md`), which will replace empty placeholder scripts under `ui/modules/` with functional layouts. 

To ensure clear scope boundaries between the UI primitives (Phase 1) and the data models/databases (Phase 2), we aligned on the following:
* **Functional Elements**: Broadcast and Context Transfer will execute **real tab automation** using the `bridge.js` primitives (`writeToInput`, `clickSend`, `clickCopyButton`).
* **Greyed-out Placeholders**: Skills prompt libraries, Orchestrator node tree graph connections, and custom profile database storage will be designed as greyed-out visual placeholders, deferring their execution engines to Phase 2.
* **Strict Domain Filtering**: Tabs queried and displayed by the active modules will be strictly filtered to the four tested platforms:
  * ChatGPT (`chatgpt.com`)
  * Claude (`claude.ai`)
  * Gemini (`gemini.google.com`)
  * Copilot (`copilot.microsoft.com`)
  * *Note*: The Debug Test module remains the sole exception to this rule.
