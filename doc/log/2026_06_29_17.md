## 1. What Changed Compared to Commit `cbb6f`

We completed the implementation, debugging, and verification of copy operations across all 4 target platforms (ChatGPT, Claude, Gemini, Copilot). This resolved key conflicts where copy actions would double-match buttons, return empty text, or extract the string `"Copied"` instead of the actual message content.

### **A. Copy Button Loading & Scanning (Virtualizer Bypass)**
* **Virtualization Bypass**: When scanning or copying, we wrap operations inside `forceDisplayAllContent(actionCallback)`. This temporarily overrides CSS `content-visibility: visible !important` page-wide and expands scroll container heights to `height: auto`, forcing React-windowing and other virtualizers to mount off-screen conversation turns.
* **Filtering Code Blocks**: Automatically excludes any copy button residing inside `pre`, `code`, or `.code-block` elements to ignore inline code copy actions.
* **Top-Down Sequential Ordering**: Buttons are dynamically sorted based on their physical DOM layout order using the `compareDocumentPosition` API, ensuring that `AI Response #1` and `User Input #1` map logically to the timeline.

### **B. Copy Button Classification (AI vs. User)**
To prevent duplicate matching or user prompt buttons overlapping with AI responses, we implemented site-specific disjoint selectors:
* **ChatGPT**: Has no copy buttons for user prompts. All copy buttons are classified under AI.
* **Claude**: Uses the same `aria-label="Copy"` and `data-testid="action-bar-copy"` for both user prompts and AI responses. We differentiate them by page alignment:
  * **User Copy**: `div.items-end button[data-testid="action-bar-copy"]` (aligned to the right).
  * **AI Copy**: Classified as any copy button that does *not* match the user selector (aligned to the left/start).
* **Gemini**: User buttons match `"button[aria-label*=\"copy prompt\" i]"`; AI buttons match `"button[aria-label*=\"copy\" i]"` (which are naturally disjoint).
* **Copilot**: Both share the label `"Copy message"`. We isolate them by their parent message turn classes:
  * **User Copy**: `.group\\/user-message button[aria-label*=\"copy\" i]`
  * **AI Copy**: `.group\\/ai-message button[aria-label*=\"copy\" i]`

### **C. Copy Button Clicking & Scraper Fallbacks**
* **Clipboard Intercept Listener**: Clicks the target button programmatically. A capture-phase listener in the main-world intercepts the clipboard write and returns it immediately.
* **Gesture Timeout Fallback**: Programmatic clicks without human interaction are blocked by browser security rules from executing clipboard writes. If the write times out (1s), we fall back to a DOM scraper.
* **Pre-Resolved Parent Turns**: Resolves parent turns (using `findParentTurn()`) *before* executing the click, preventing failure if the button gets detached or disabled post-click.
  * **Gemini Tag Fix**: Updated `messageTurnSelector` from `div.message-content` to `message-content` to match Gemini's native custom tag container `<message-content>`.
* **Narrow Fallback Scraper**: Excluded the overly broad class selector `[class*="message" i]` (which mistakenly matched Tailwind modifiers like `group-hover/user-message:opacity-100` on toolbar containers, returning the button text `"Copied"`). It now queries `.markdown`, `message-content`, `.message-content` specifically, defaulting to `|| targetTurn` (the turn box text) if no inner matches are found.

## 3. Maintenance and Expansion Playbook

### **A. How to handle UI Updates from Target Platforms**
* **Centralized Profiles**: All selectors and flags are isolated in [background.js](../../background.js) and the `presets/` directory. **Never hardcode site-specific logic in the interaction engine ([bridge.js](../../bridge.js)).**
* **Adjustment Process**: If a site updates its layout and scanning fails:
  1. Open the Debug Test console.
  2. Perform a button scan or copy action to generate the diagnostic report.
  3. Look at the printed `Parent Chain` tags/classes to identify the new wrapping containers.
  4. Update the selector fields inside the corresponding profile in [background.js](../../background.js).

### **B. How to support a New Platform**
1. Add a new configuration entry in the `defaultProfiles` object inside [background.js](../../background.js).
2. Create a corresponding JSON profile inside the [presets/](../../presets/) directory.
3. Hook up the selectors:
   * Define the `messageTurnSelector` representing the wrapper containing a single Q&A turn.
   * Define `copyButtonSelector` and `userCopyButtonSelector` (if the site supports copying user inputs).
4. Run the Sandbox tester and Debug Test console to verify.
