# 2026-10-26 — Phase 3 design: memory-centred workflow, prompt tests, plan

- **Goal:** Decide what to build after v0.6.0, using the old spec/plans, and test the prompting strategy live.
- **Timing:** 2026-10-26 ~18:00–21:00 CDT.
- **Status:** completed (design + experiments + plan; no extension code changed).
- **What changed:**
  - `doc/experiments/memory_workflow/`: `prompts_v2.md` (script prompts), test briefs, `round2_log.md` (Chicago trip),
    `round2b_log.md` (blog post), `flow_round2.html` (visual summary).
  - `doc/plan/phase_3_plan.md` (new): Projects screen, engine in background, dev harness, work steps, risks.
- **What was found:**
  - The old Orchestrator's real purpose was context control (spec §4: parent context stays clean, read only the last
    answer). The new design keeps that purpose with a versioned memory as the hub instead of a tab tree.
  - Positioning (user, 2026-10-26): the advantage over provider "work" modes is owning the whole workflow (plan, memory,
    routing, record), so the provider can be switched halfway, plus human control of each step.
  - Prompt taxonomy: `@` actions, `+` modifiers (appended under "Output requirements:"), `%` wrappers/formats (system).
  - Round 1 (CHI paper, GPT agent): memory update turned proposals into decisions, silently removed an open question,
    used earlier chat context; result blocks lost candidates and links.
  - Round 2 (prompts v2, Gemini agent, two tasks): `+short` worked (16–85 words outside the block); hand-offs kept all
    Return items and links; memory updates tagged decisions `〔AI · basis〕` and explained removed questions; resume on
    the other site did not re-argue decisions; `%fix` worked. Gemini's trailing follow-up line is the page's suggestion
    chips (`.follow-up-container`), not model output.
  - User decisions: AI may make decisions, the user reviews the diff; "notes" means user-written memos with AI help
    (later topic); many chats per small task pollute history (later topic; worker tabs auto-close for now).
- **Validation:** live runs on ChatGPT and Gemini (/u/2) logged in the experiment folder.
- **Conclusion:** Plan ready for user approval.
- **Next steps — Codex can proceed:** after approval, Phase 3 steps 0–6.
- **Next steps — Human reflection:** user notes module; how to keep chat history tidy.
- **Human action:** approve `doc/plan/phase_3_plan.md`; still open from v0.6.0: test side panel / `;;` / notifications,
  record GIFs, approve release + MIT license.

## 2026-10-26 — Phase 3 implementation: Projects screen, engine, live end-to-end test

- **Goal:** implement `doc/plan/phase_3_plan.md` (steps 0–6, 8), test it, then run it live with Claude in Chrome.
- **Timing:** ~21:15–22:15 CDT (~1 h), branch `phase-3-projects`.
- **Status:** completed (waiting on the user's hand trial, step 7).

### What changed
- `utils/workflow_prompts.js` (Gemini worker): prompt texts, message builders, `parseBlock` / `parseTasks` /
  `parseMemoryAnswer`, `diffMemory`. `test/workflow_prompts.test.js`: 15 tests from real round-2 answers.
- `utils/project_store.js` (Gemini worker): projects, memory versions, tasks, steps, archives; serialized writes.
  `test/project_store.test.js`: 8 tests.
- `utils/workflow_engine.js` (new): step runner in the background + `wf_*` message API.
- `bridge.js`: `getGenerationSnapshot` (quiet poll: stop button, answer copy count, input length, URL); copy result
  says whether text came from the clipboard or the DOM fallback.
- `background.js`: loads the engine; refuses tab-driving messages (`bridgeCommand`, `switchTab`, `wf_*`) from web
  pages except localhost with Dev harness on; side panel is the default view (existing installs switch once); toolbar
  click no longer awaits storage before `sidePanel.open`.
- `content.js`: the `agyTestRequest` relay only works on localhost with Dev harness on (it used to let any page drive
  chat tabs).
- `ui/manager.html|js|css`, `ui/modules/projects.js`: Projects screen (first in the sidebar), settings "Keep chat
  tabs open" and "Dev harness" (debug only).
- `test/harness/index.html` (localhost harness, `window.harness`), `test/ui_preview/` (headless screenshots with a
  stubbed chrome API).
- `README.md`, `doc/roadmap.md` updated.

### What was found
- GPT review (11 findings, all fixed): Continue closed its own chat; DOM-fallback text skipped the focused copy retry;
  partial memory answers dropped sections; parseBlock took text up to the last fence in the answer; malformed plans
  accepted; drafts leaked across projects; double Send.
- Live, ChatGPT: the send button appears a beat after the text is typed; clicking at 0.4 s fell back to a synthetic
  Enter that ChatGPT ignores. Fix: press send until the box empties / URL changes / stop button shows.
- Live, Gemini: answers are not drawn in hidden tabs (only the user turn exists). Fix: after 3 idle polls the engine
  shows the tab for 1.5 s ("peek"). Gemini task then finished in < 30 s.
- Works live: copy-read returns raw Markdown (`source: clipboard`) on both sites; ChatGPT web-search answers are
  detected as done only at the end; ChatGPT `?temporary-chat=true` works for memory updates; `%fix` repaired a
  missing block; a service-worker restart marks running steps "Interrupted" and the task "Needs you"; Continue on
  Gemini used the decisions without re-arguing them.
- Headless Chrome has a minimum window width; narrow screenshots must use an iframe.

### Validation
- `node test/workflow_prompts.test.js` 15/15, `node test/project_store.test.js` 8/8.
- Headless screenshots (light/dark, window/panel width, updated-memory state).
- Live via harness: project "Note app pick" — split (ChatGPT) → tasks (ChatGPT 17 links, Gemini 3 links) → memory v1
  (ChatGPT temporary chat, decisions tagged 〔AI · basis〕) → Continue on Gemini (10-step checklist). Separate `%fix`
  project (deleted after).
- Not tested live: the Projects screen itself (Claude in Chrome can't open extension pages), "Needs you" after a failed
  `%fix`, Claude/Copilot.

### Conclusion
The memory-centred workflow runs end to end inside the extension on ChatGPT and Gemini. Ready for the user's trial.
