# 2026-10-26 — Demo release v0.6.0, first build

- **Goal:** First working build of the Phase 2.5 plan, ready for the user to try on ChatGPT and Gemini in Chrome.
- **Timing:** 2026-10-26 ~16:45–17:30 CDT.
- **Status:** completed (needs the user's hands-on test).
- **What changed:**
  - `ui/manager.html`: three screens (Send, Prompts, Settings) + Debug (only with `?debug`); no web fonts; Context
    Transfer, Broadcast and Orchestrator views removed from the page (their JS files are kept, not loaded).
  - `ui/modules/send.js` (new): tab list with checkbox, site name, live status chip, click-to-jump, per-tab
    "Quick prompt" menu; composer with `@` autocomplete and Cmd/Ctrl+Enter; one-line result message.
  - `background.js`: "Answer ready" notification when a watched tab goes working → complete while not in front;
    click focuses the tab; can be turned off (`notifyWhenDone`).
  - `ui/manager.css`: rewritten — flat, system font, one accent color, follows OS light/dark.
  - `ui/manager.js`: new module map, notification setting, debug view hidden unless `?debug`.
  - `ui/modules/skills.js`, `utils/skills_registry.js`: plain wording; default prompts are @redo, @continue,
    @shorten, @check; old workflow prompts (@breakdown, %transfer, %format, %merge) removed on load.
  - `content.js`: the in-page `@` pop-up is now on by default (was off until enabled in the UI).
  - `manifest.json`: v0.6.0, `notifications` permission, PNG icons 16/32/48/128; `icons/icon.svg` redrawn.
- **What was found:** the in-page `@` pop-up was off by default, so a new user would never see the headline
  feature. Status updates only flow while the manager is open (observers are registered from the Send view).
- **Validation:** `node --check` on all changed JS; headless-Chrome screenshots of Send / Prompts / Settings in light
  and dark. Not yet run as a loaded extension.
- **Conclusion:** First build is ready to try.
- **Next steps — Codex can proceed:** fix whatever the trial finds; README with GIFs; tick roadmap; tag and release.
- **Next steps — Human reflection:** after trying it, which of Send / quick prompt / notifications feels useful.

# 2026-10-26 — Phase 3 design: memory-centred workflow, prompt tests, plan

- **Goal:** Decide what to build after v0.6.0, using the old spec/plans, and test the prompting strategy live.
- **Timing:** 2026-10-26 ~18:00–21:00 CDT.
- **Status:** completed (design + experiments + plan; no extension code changed).
- **What changed:**
  - `doc/experiments/memory_workflow/`: `prompts_v2.md` (script prompts), test briefs, `round2_log.md` (Chicago trip),
    `round2b_log.md` (blog post), `flow_round2.html` (visual summary).
  - `doc/plan/phase_3_plan.md` (new): Projects screen, engine in background, dev harness, work steps, risks.
- **What was found:**
  - The old Orchestrator's real purpose was context control (spec §4: parent context stays clean, read only the last
    answer). The new design keeps that purpose with a versioned memory as the hub instead of a tab tree.
  - Positioning (user, 2026-10-26): the advantage over provider "work" modes is owning the whole workflow (plan, memory,
    routing, record), so the provider can be switched halfway, plus human control of each step.
  - Prompt taxonomy: `@` actions, `+` modifiers (appended under "Output requirements:"), `%` wrappers/formats (system).
  - Round 1 (CHI paper, GPT agent): memory update turned proposals into decisions, silently removed an open question,
    used earlier chat context; result blocks lost candidates and links.
  - Round 2 (prompts v2, Gemini agent, two tasks): `+short` worked (16–85 words outside the block); hand-offs kept all
    Return items and links; memory updates tagged decisions `〔AI · basis〕` and explained removed questions; resume on
    the other site did not re-argue decisions; `%fix` worked. Gemini's trailing follow-up line is the page's suggestion
    chips (`.follow-up-container`), not model output.
  - User decisions: AI may make decisions, the user reviews the diff; "notes" means user-written memos with AI help
    (later topic); many chats per small task pollute history (later topic; worker tabs auto-close for now).
- **Validation:** live runs on ChatGPT and Gemini (/u/2) logged in the experiment folder.
- **Conclusion:** Plan ready for user approval.
- **Next steps — Codex can proceed:** after approval, Phase 3 steps 0–6.
- **Next steps — Human reflection:** user notes module; how to keep chat history tidy.
- **Human action:** approve `doc/plan/phase_3_plan.md`; still open from v0.6.0: test side panel / `;;` / notifications,
  record GIFs, approve release + MIT license.
